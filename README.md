# ZENTORA ホームページ 公開手順

このフォルダには、公開に必要なファイルが揃っています。

```
index.html               … サイト本体（1ファイルで完結）
api/contact.js           … Vercel用のフォーム処理関数
functions/api/contact.js … Cloudflare Pages用のフォーム処理関数
```

Vercelを使うなら `functions/` フォルダは不要、Cloudflare Pagesを使うなら `api/` フォルダは不要です。片方だけ残して構いません。

---

## 事前準備: Notion連携の情報を2つ用意する

### ① データベースID

お問い合わせデータベースは作成済みです。IDは次の通りです。

```
c0d6bf439c374c459adb4daf1d6fb5e9
```

（データベースのURL `https://www.notion.so/…/c0d6bf439c374c459adb4daf1d6fb5e9?v=…` の、末尾の `?v=` より前の32文字部分です）

### ② インテグレーションのトークン（新規発行が必要）

公開サイトがこのデータベースに書き込むための鍵です。

1. `https://www.notion.so/my-integrations` を開く
2. 「新しいインテグレーション」を作成
   - 名前: `ZENTORA HP Contact` など
   - 種類: 内部インテグレーション
   - ワークスペース: ZENTORAのワークスペース
3. 作成後に表示される「内部インテグレーションシークレット」をコピー
   （`ntn_…` または `secret_…` で始まる文字列）
4. お問い合わせデータベースを開き、右上「…」→「接続」→ 今作ったインテグレーションを追加
   ※この接続を忘れると、トークンがあっても書き込めません

## 公開手順（Vercelの場合）

1. **GitHubリポジトリを作成**し、このフォルダの中身をpush
   （`functions/` は削除してよい）
2. **Vercel**（vercel.com）でGitHubリポジトリをインポート
3. デプロイ設定はデフォルトでOK（フレームワークなし、ルートに index.html）
4. **環境変数を登録**（Settings → Environment Variables）
   | 変数名 | 値 |
   |---|---|
   | `NOTION_TOKEN` | 発行したインテグレーションのトークン |
   | `NOTION_DATABASE_ID` | `c0d6bf439c374c459adb4daf1d6fb5e9` |
5. 再デプロイ（環境変数は再デプロイ後に反映される）
6. 発行されたURL（`〇〇.vercel.app`）でフォームからテスト送信
7. Notionのデータベースに入れば成功

---

## 公開手順（Cloudflare Pagesの場合）

1. **GitHubリポジトリを作成**し、このフォルダの中身をpush
   （`api/` は削除してよい）
2. **Cloudflare Pages**でGitHubリポジトリを接続
3. ビルド設定: フレームワークなし、ビルドコマンドなし、出力ディレクトリはルート
4. **環境変数を登録**（Settings → Environment variables）
   | 変数名 | 値 |
   |---|---|
   | `NOTION_TOKEN` | 発行したインテグレーションのトークン |
   | `NOTION_DATABASE_ID` | `c0d6bf439c374c459adb4daf1d6fb5e9` |
5. 再デプロイ
6. 発行されたURL（`〇〇.pages.dev`）でフォームからテスト送信

---

## 独自ドメイン（zentora.jp）の切り替え

1. ホスティング先（Vercel / Cloudflare Pages）の管理画面で `zentora.jp` を追加
2. 表示される指示に従い、DNSレコードを設定
   - 現在のドメイン管理先（zerositeの契約先、またはお名前.com等）の管理画面で、AレコードまたはCNAMEを新ホスティング先に向ける
3. DNSの反映には数分〜数時間かかる
4. 反映後、`https://zentora.jp` で表示・フォーム送信を最終確認

⚠️ 切り替え前に、現行サイト（zerosite）の契約や、メール等が同じドメインで動いていないかを確認してください。動いている場合は、そのレコードは残す必要があります。

## テスト送信データの削除

動作確認で作成した「テスト 太郎」のデータが1件、Notionのデータベースに入っています。
本番前にNotionの画面から削除してください。

---

## 公開後の運用

- 新しいお問い合わせは、Notionのデータベースに「未対応」ステータスで入ります
- 通知が欲しい場合、Notionのデータベースオートメーションで「新規ページ追加時にメール送信」を設定できます
- 対応状況は「ステータス」列（未対応／対応中／完了）で管理できます
